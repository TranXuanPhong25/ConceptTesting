# Experiment

----

This module has all scripts necessary to reproduce the experimental results to replicate the experiments on the ground truth dataset, with Tratto, Jdoctor, and GPT4.
The experiments cover the third research question of the paper `Tratto: A Neuro-Symbolic Approach to Deriving Axiomatic Test Oracles`, and measure what is the 
effectiveness of Tratto in generating axiomatic test oracles and how it compares with state-of-the-art neural and symbolic techniques.

# 1. Overview

----

## 1.1. Research Questions

As a precursor, we define an "axiomatic" oracle, as a self-evident and unquestionable oracle (e.g. `methodResult != null`).
Axiomatic oracles are very general and not specific to individual test prefixes.

In our experimental analysis, we seek to answer what is the effectiveness of Tratto in generating axiomatic test oracles
and how does it compare with state-of-the-art neural and symbolic techniques.

## 1.2. Metrics

To answer the above research question, we evaluated Tratto in generating axiomatic oracles on a ground truth of `15`
popular Java projects. We measured the number of `true positives`, `false positives`, `true negatives`, and `false negatives` 
oracles as well as the corresponding `accuracy`, `precision`, `recall`, and `F1-score`, and we compared the results with 
the axiomatic oracles generated with state-of-the-art symbolic and neural techniques, such as 
[Jdoctor](https://github.com/albertogoffi/toradocu) and [GPT4](https://openai.com/index/gpt-4/) respectively.

# 2. Run the experiments

----

This section outlines all requirements and corresponding setup instructions for each tool used in the experimental pipeline.
It also provides the necessary commands to run the experiments.

**Note**: The results of the experiments are already available within the folder `experiment/output`, for both `tratto`, `jdoctor`, and `GPT4`.

## 2.1 Tratto and Jdoctor

To run the experiment with Tratto and Jdoctor, you need to setup the environment.

First of all, check to have **zip** and **unzip** packages installed in your machine. Otherwise, check these webpage to install
them with the proper command ([zip](https://www.thegeekdiary.com/zip-command-not-found/) and [unzip](https://www.thegeekdiary.com/unzip-command-not-found/)).

Then, execute the command:

```shell
  bash ./generator/utils/init.sh
```

To download and install a local version of [Sdkman](https://sdkman.io/). **Sdkman** is a Software Development Kit (SDK) manager
used to easily manage the multiple Java Development Kit(s) (JDKs) required by the different tools of the experimental pipeline. 

The script will also install a local version of:

* Java 8
* Java 17
* Maven 3.9.4
* Ant 1.10.13
* Gradle 8.3

After completing the setup, to perform an experiment, run the command:

```shell
  bash ground_truth.sh [tog_name] {[port_number]}
```

providing 1 (or 2) argument(s) as input:
1. the TOG name [`jdoctor`,`tratto`]
2. In case the value of the first argument is `tratto`, the port number to communicate with the server where the neural module is running.

If `tratto` is used, remember to start the server within `[tratto_replication_package_path]/ml-model` following the instructions
in the corresponding `README.md` before to run the experiments.

## GPT4

The folder `[tratto_replication_package_path]/experiment/generator/open_ai` contains all the scripts to run the experiments with GPT4.
To execute calls to the GPT4 API, you need to have an API key. The key must be placed in the file `.env` within the folder `open_ai`.
The file must contain the following line:

  ```shell
    OPENAI_API_KEY=your_private_api_key
  ```

Note that the results obtained with GPT4 can be different from the ones reported in the paper, as the model is continuously updated and improved
and it does not guarantee the same results across different runs.

The command:

```shell
  python3 open_ai_upload_files.py
```

uploads the batches of requests to the GPT4 API. The results are stored in the folder `open_ai/results`.

The requests are generated using the prompt template in `generator/open_ai/query.txt`.

The command:

```shell
  python3 open_ai_batch_run.py
```

executes the requests on the server side of OpenAI.

The command:

```shell
  python3 open_ai_batch_retrieve_result.py
```

download the responses generated by the GPT4 model on the server side and save them within the folder `generator/open_ai/output_batches`.

# 3. Analyze the results

To quickly analyze the results of the experiments, you can refer to the following documents:

* `analysis/gt-pre-post-throws-complete-analysis.xlsx` classifies all the preconditions, normal and exceptional postcondition generated by Tratto, Jdoctor (on the whole ground truth dataset), and GPT4 (limited to the methods for which preconditions and regular or exceptional postconditions are defined. The reason is the huge number of false positives generated by GPT4 that make it impossible to analyze the whole dataset manually).
* `analysis/replication-dataset-gt-analysis.xlsx`reports the results of the experiments on the ground truth dataset, reporting the count of true positives, false positives, true negatives, and false negatives, as well as the accuracy, precision, recall, and F1-score of Tratto, Jdoctor, and GPT4.
