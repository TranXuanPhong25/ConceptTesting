# Prompt engineering in LLMs for automated unit test generation: A large-scale study

Reviewed 2026-10-15 using the author-hosted 58-page manuscript, not the local Springer abstract page. Extracted full text: 22,895 words; SHA-256 `e7eb5f58ace8d64c9b1c03cf6eb565775b72557ee2bb5cd6662a9d6084872b4a`. Article: EMSE 31(4), Article 103, DOI [10.1007/s10664-026-10840-4](https://doi.org/10.1007/s10664-026-10840-4).

The final 2026 article evaluates four legacy LLMs (GPT-3.5, GPT-4, Mistral 7B, Mixtral 8×7B), five prompts (ZSL/FSL/CoT/ToT/GToT), class-level JUnit generation and EvoSuite on Defects4J (477 classes/16 projects), SF110 (182 classes), and a 31-class post-2023 CMD. It runs 30 repetitions per setting and counts 216,300 generated outputs. It finds severe compile/hallucination issues; reasoning prompts improve some measures, while EvoSuite remains stronger on structural coverage. However, the final paper explicitly says it does **not** evaluate F2P paired buggy/fixed bug detection, exception-based fault detection, or mutation analysis. Defects4J is used for compilation/coverage/quality, not direct real-bug exposure. This is a critical scope limitation for our main task.

The paper-linked [anonymous replication package](https://anonymous.4open.science/r/LLM4TS-0F76/) is public/MIT, but appears to be an older 2024 package: its README title/citation is “Exploring Prompt Engineering…”/2024, and 4open reports source commit date 2024-09-26. The visible package includes dataset JSONs, hundreds of dependency JARs, generated test files and some RQ1/RQ2 scripts/results, but the root lacks RQ3/RQ4 and Test-Generation directories claimed by the README, and only GPT-3.5-Turbo/EvoSuite output roots are visible. Therefore the exact link between this old artifact and the final 2026 article is unresolved; not all paper runs or code are available. A 2024 arXiv predecessor exists and has a different title/version with bug-detection experiments; do not conflate it with the final 2026 version.

There is also an internal manuscript contradiction: §5.2.1 explicitly says no mutation/fault-detection experiments, but §6.5 briefly claims mutation testing was integrated. The actual RQ list/results do not contain mutation or F2P tables; follow the explicit limitations and results, and record this as an inconsistency.

**Recommendation:** useful supporting paper for prompt/output validity and whole-class generation, but not a primary bug-revealing test paper or an easy exact reproduction. Inspect the old package as historical output evidence only after resolving version mapping.
