# Papers for ConceptCoder-inspired bug-exposing tests with Gemini

Reviewed 2026-09-25 against primary papers and released artifacts. Goal: generate a test that demonstrates a bug, not merely covers a line. `ConceptCoder` learns statement-level semantic labels through supervised multi-task fine-tuning of open-weight models; using Gemini as an API generator with externally computed concepts is an **adaptation**, not a reproduction of its training method. [ConceptCoder paper](https://arxiv.org/html/2603.23470).

## Recommended order

| Rank | Paper and role | Concept insertion point | Bug oracle and effort |
| ---: | --- | --- | --- |
| 1 | [TrickCatcher, ACL 2025](https://aclanthology.org/2025.acl-long.20/) — method; [artifact](https://github.com/RinCloud/TrickCatcher) | From the specification and suspicious code, infer a compact *failure mechanism*: expected invariant, implementation shortcut, input partition that separates them. Feed it into Gemini's program-variant and input-generator stages; validate that generated inputs satisfy it. | Differential execution on plausible buggy programs and variants; reference outputs in the benchmark can score suspected bugs. Python subset of TrickyBugs/EvalPlus is a manageable first pilot. Main novelty must be verified concepts, since TrickCatcher already uses specifications and program variants. |
| 2 | [TestCase-Eval Task 2, ACL 2025](https://aclanthology.org/2025.acl-short.82/) — benchmark; [artifact](https://github.com/FlowRays/TestCase-Eval) | Analyze the wrong submission into a fault hypothesis, required input relation, and expected correct behavior. Let Gemini construct an input; execute it on wrong and accepted implementations. | Official Fault Exposure is directly aligned with bug detection. This repo already has a runner, but its earlier regex concept arm got 10/113 vs 12/113 for baseline, and 78/113 cases lacked a Python accepted-solution oracle in the lite split. Fix oracle availability before drawing a new conclusion. [Local result](../testcase_eval/RESULTS.md). |
| 3 | [TestExplora, 2026](https://arxiv.org/html/2602.10471) — real-repository benchmark; [artifact](https://github.com/microsoft/TestExplora) | Derive concepts only from pre-fix code and documentation: intended postcondition, controllable entry point, cross-module state, and an input class that may violate the postcondition. Use Gemini to write tests. | Fail-to-Pass on buggy/fixed repository revisions. The benchmark has a Gemini call path and a Lite slice. Most convincing real-bug external validation, but Docker/dependency setup across repositories is substantially more expensive. Never expose the hidden patch, issue details, or gold test to the concept extractor. |
| 4 | [VulEUT, FORGE 2025](https://arxiv.org/html/2409.16701) — security method; [artifact cited in paper](https://anonymous.4open.science/r/VulEUT-38B3) | Replace loose code snippets with a checked chain: entry input → parameter transformations → vulnerable guard/sink → expected safety impact. Gemini constructs the client-side unit test. | Exploit-confirming execution on 32 vulnerabilities and 70 Java client projects in the paper. Closest *task semantics* to ConceptCoder's vulnerability concepts, but its seven C memory labels need redesign for Java and the Soot/Maven setup is heavy. VulEUT already performs reachability analysis, so the added concept must improve trigger selection or oracle quality beyond that baseline. |
| 5 | [Mokav, JSS 2025](https://arxiv.org/html/2406.10375) — differential method; [artifact](https://github.com/ASSERT-KTH/mokav) | Convert two programs' execution traces into an explicit divergence concept: variable/state difference, condition to amplify it, and output that should diverge. Gemini proposes the next input. | Difference-exposing test on C4DET/QuixBugs. Easy Python oracle and public code, but Mokav already feeds fine-grained value differences to the LLM and reports 1,255/1,535 C4DET pairs found; concept prompts may be redundant or face a ceiling. |

Supporting comparator: [MitGen, TOSEM 2026](https://doi.org/10.1145/3793675) localizes small program snippets and generates failing tests; its [artifact](https://mitgent.github.io/MitGen-s-Artifact/) is public. ConceptCoder labels could rank relevant snippets and formulate an input/oracle relation, but this requires an additional localization study. The publisher full text was not accessible during this review, so treat this as a backup candidate rather than a fully verified first choice.

If preserving ConceptCoder's original **C/C++** label vocabulary is the main constraint, [STRUT, ISSTA 2025](https://doi.org/10.1145/3728970) offers structured seed tests for C functions. It reports execution and structural coverage; combine its generator with an independent Magma/ASAN or red-green bug oracle before claiming improved bug detection. Existing local Magma concept-prompt results caution against merely appending tags.

No row is a drop-in application of the released ConceptCoder classifier. Its seven vulnerability labels were designed for C/C++ reasoning. For the Python candidates, define test-relevant statement labels, generate training labels with static analysis and/or execution, and train a small concept predictor. Compare its predicted labels with tool-derived labels and shuffled labels when conditioning Gemini. For VulEUT's Java code, the same redesign is needed for Java sinks and guards. The current configured Gemini `gemini-3-flash-preview` can serve as the generator; these experiments do not fine-tune Gemini.

## Important overlap and null evidence

- [SeGa, ISSTA 2026](https://arxiv.org/html/2604.23509) already extracts preconditions, triggering actions, expected outcomes and constraints from requirements to guide test generation. A paper whose sole change is “put those fields in the Gemini prompt” would have weak novelty.
- [ConceptCoder](https://arxiv.org/html/2603.23470) reports gains from concept **supervision** on smaller open-weight models. It also reports that hierarchical prompting alone did not address the same reasoning challenge. An external concept block in Gemini should be named honestly and checked causally.
- Local Gemini trials found no stable gain from simple tags/boundaries: TestCase-Eval regex concepts 10/113 vs baseline 12/113; TestEval mutation pilot 35/39 vs 35/39; richer full-guard mutation concept 29/36 vs 28/36 at three attempts; CrossProbe transfer smoke had one fidelity improvement and one regression. These results do not rule out concepts; they show that prompt-only annotations are insufficient evidence. See [mutation pilots](mutation-full-guard-holdout-2026-09-24.md) and [CrossProbe smoke](crossprobe-concept-smoke-2026-09-24.md).

## Concrete first experiment

Choose **TrickCatcher's Python subset**, then confirm on **TestCase-Eval Task 2**. For each PUT and specification, create a public concept record with three fields:

1. `expected_property`: an invariant or postcondition grounded in the specification;
2. `suspected_shortcut`: the actual statement/pattern in the PUT that may violate it;
3. `separating_input_relation`: valid input constraints that make the shortcut disagree with the property.

Keep `oracle_source` private to the evaluator: an independently executed accepted/reference version or specification rule. Neither Gemini nor the concept extractor may see that implementation or its outputs before proposing the test. The buggy PUT's output must not be treated as the expected result.

Give the same Gemini model, sampling budget, code/specification context and execution feedback to these paired arms: official method prompt; length-matched generic reasoning; concept record; shuffled/mismatched concept record; and concept plus a deterministic adherence/oracle validator. Keep concept extraction blind to hidden fixes and gold tests. Measure **bug-exposing recall/Fault Exposure as primary**, then input validity, oracle accuracy, false positives, concept adherence, calls/tokens and runtime. Report matched pairs and cluster by problem/repository, not only aggregate test counts.

If concept only improves when the oracle validator is present, claim a *verified semantic bottleneck*, not a prompting gain. If it cannot beat a length-matched and shuffled control, stop the direction before scaling Gemini calls.
