## Scope and Method

- Years: publication/venue year 2025 or 2026. VulEUT has a 2024 arXiv preprint but is included because its peer-reviewed FORGE publication is 2025.
- Discovery used OpenAlex across 25 test-generation/fuzzing/bug/security queries; OpenAlex was discovery metadata only. Links below point to the paper owner (DOI, arXiv, ACL, ICLR, or publisher).
- P0 = directly useful for concept-guided fault detection/fuzzing/oracles; P1 = direct test-generation method; P2 = benchmark, survey, or adjacent analysis.
- “Method” and “concept hook” are concise research syntheses from titles/abstracts; read the linked paper before claiming implementation details.

## Reusable Method Patterns

| Pattern | Representative papers | How to apply `concept` | Primary metric |
|---|---|---|---|
| Program-analysis guided generation | PALM, Static Analysis + LLM, logic-guided testing, VulEUT | Convert guards, data flow, sinks, and path constraints into target-specific concept blocks. | Coverage, reachability, trigger rate |
| Mutation-guided generation | Meta ACH, PRIMG, GEM, mutant-driven smart contracts | Encode mutant operator and surviving behavior as the target concept; iterate until killed. | Mutation score / mutants killed |
| Differential testing | Mokav, LWDIFF, DrWASI, database connectors, RustAssure | Encode cross-implementation semantic relation and disagreement conditions. | Unique discrepancies / confirmed bugs |
| Metamorphic testing | MORTAR, SVPrompt-MR, LLMorph, property-based generation | Treat each metamorphic relation as a concept plus source-to-follow-up transformation. | MR violations / fault detection |
| Directed fuzzing | LLAMAFUZZ, CKGFuzzer, Clozemaster, kernel fuzzing | Concept describes grammar state, target edge, changed fields, or vulnerability guard. | New coverage / crashes / CVEs |
| Oracle strengthening | TOGLL, AugmenTest, AutoOracle, Doc2OracLL | Concept is a postcondition/invariant and source of authority; filter unsupported assertions. | Assertion accuracy / bug detection |
| Execution-feedback loops | CoverUp, LLMLOOP, YATE, Retry and Refine, TestLoter | Feed back syntax/runtime/assertion/coverage/fault status while preserving concept state. | Pass rate / coverage / F2P |
| Red-green / fault exposure | TestCase-Eval, TestExplora, VulEUT, Less Is More | Concept is the hypothesized defect; same test must fail buggy and pass fixed/correct code. | Fault Exposure / Fail-to-Pass |

## Recommended Experiment Sequence For This Repo

1. **TestCase-Eval Task 2:** baseline vs static-concept vs concept+feedback on the Python/PyPy subset; report Fault Exposure.
2. **Mutation ablation:** generate controlled mutants for TestEval/ULT functions; use mutant kind as the concept and report mutation score.
3. **TestGenEvalLite:** inject file/dependency concepts and measure pass@1, coverage improvement, and mutation score.
4. **VulEUT/Magma:** use sink/guard/fault-condition concepts and require vulnerability-triggering red/green behavior.
5. **TestExplora:** only after the smaller semantic experiments are stable; measure repository-level F2P and F2P@k.
