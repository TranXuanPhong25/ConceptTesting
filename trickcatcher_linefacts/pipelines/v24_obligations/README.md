## Scope and truth boundaries

Nine seen authored fixtures: sorted multiplicity f01/f02/f14/f15, inclusive count
f03/f04, inclusion f05/f06 and ambiguous f13.3buggy,5correct,1ambiguous. One full
returned-value obligation per function, not a general arbitrary-spec/multi-obligation
compiler. No copy-identity/all-side-effects claim. No benchmark/held-out progression.

Qwen proposes exact spec quote, original domain, relation, uncertainty and pure Python
`obligation(arguments, observation)` from **signature/spec only**. Observation is an
ok JSON value or an exception status. Code-only behavior extraction sees masked code
and syntax. Both feed a single hypothesis with one target statement and a pure
`trigger(arguments)`. Qwen retains semantic responsibility; tools never match a
property/fault label to a code effect or choose a fault from an AST pattern catalog.

Predicate syntax is checked against a pure AST/call subset. Native PUTs and predicates
execute in isolated network-free processes with time/memory caps; workers receive no
credentials. Boolean results required, mutation rejected, runtime errors unknown.
Native/traced outputs/status/exceptions/input mutation/alias signatures must agree.
Trace verifies line reach only, not data propagation or universal path conditions.

**Semantic calibration uses diagnostic gold explicitly.** A frozen authored positive/
negative output bank checks full JSON output relations, strict bool/int distinction,
exceptions, empty cases, duplicates, ordering, boundaries and extras. Passing this bank
is finite authored calibration, not proof of correct spec interpretation or a deployable
reference-free verifier. No failing bank row/expected output is sent to Qwen, no
predicate repaired/replaced. f13 has no normative oracle: raw confident predicates
remain preserved but unqualified. Separate independent semantic audit remains needed.

Original-domain filter is fixed; model domain prose cannot narrow it. Model arguments
are named JSON objects bound by inspect.Signature, so no tuple-literal syntax is needed.
Output synthesis is outside this first input-generation diagnostic; post-freeze scoring
uses the SAME independent fixture oracle for every arm. Property assertions are not
silently substituted as the experimental scoring oracle.

## Fixed evidence and controls

Before calls,24 type-only Hypothesis draws/task freeze with seed20261017+fixture ID,
max128 examples, database disabled, integers[-2,3], lists0..4; public base inputs added.
Library/interpreter versions and all source/input/bank hashes are recorded. No PUT
constants, fault labels, normative semantics or hidden bug witnesses shape this pool.

Calibration banks exhaust lists over[-1,0,1] size0..2 and scalar limits[-1,0,1], with
typed candidate observations; they are qualification data, not discovery inputs.
Independent spec oracles are used for calibration by explicit diagnostic design and
again only after generation freeze for efficacy scoring. No score-driven input search.

Hypothesis support requires a calibrated obligation, model mismatch, true trigger,
observed target-line hit and false obligation on the SAME native-verified row. An
observed trigger counterexample makes the trigger contradicted; errors remain unknown.
No witness means unverified, not infeasible. A predeclared feedback call may revise
the hypothesis/trigger using the same pool; it cannot edit the frozen obligation.
Initial/final proposals, contradictions and validation failures remain in artifacts.

One frozen selector prefers supported witnesses, then contract violations, then original
pool order. ALL arms receive the identical up to6 concrete pool inputs/native traces.
Every concrete witness supporting the package is among those common rows; no private
trace/witness is attached only to one generation arm.

This tests the executable-verification system intervention, not pure wording, token
parity or reference-free benchmark efficacy. Shared preparation costs are separate.
