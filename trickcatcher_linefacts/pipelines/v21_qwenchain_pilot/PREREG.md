## Method and interface

Five stages per reviewed PLAN_QWEN_REASONING_CHAIN.md. S1 gets original spec/signature/public examples; S2 independently gets executable masked module source+syntax IDs, no spec/docs/comments/inferred concepts. S3 Qwen aligns candidate requirements and actual behavior; S4 proposes direct tuples; tools execute; S5 revises/withdraws with feedback and optional final tuples. No static semantic matching or fault registry. Upstream transport/schema failure blocks descendants; valid no-mismatch may terminate. No upstream reconstruction, no content repairs or extra generation retries. S1 and S2 remain independently attempted.

Pre-output production interface adaptations: exact JSON object shapes/field examples and decoded-spec character count added to help formatting. Model-facing source IDs N* and claim IDs O*/B*/H* are exact task/request-bound aliases; tool persists bijective maps and expands ONLY reference fields before unchanged validators. Local IDs/semantic prose are untouched; unknown/ambiguous aliases fail. Full source/global artifact IDs/lineage/raw+normalized responses retained. This is transport normalization, not a semantic selection rule.
