## Interpretation

The known useful mechanisms were already retrieved. Opening BM25/dense recall
mostly added contextually related or mismatched proposals; the shared lexical
binder and AST-type compatibility do not verify causal applicability. This matches
the code contract: new obligations remain unknown, contract quotes are unaligned,
and the binder cannot infer a normative requirement from similarity.

Model/context limitations remain explicit: site cap64, character caps and runtime
512token cap; global recall views can combine multiple functions. No parameters
were changed after these results. These are implementation limits, not grounds
for enlarging/retrying the same diagnostic until it wins.

Vr9 is a separate frozen repair of downstream hypothesis refutation and valid
input retention, with a pending expected-output run at the start of this task.
Its result should be completed/reported independently. V7 should remain opt-in;
no dense→vr9 integration is justified by this diagnostic.
