# vr13: two operation-role completeness corrections

2026-10-29. New development version after inspecting vr11's exposed-data
regression. Vr11 pruned many unrelated proposals but lost known first sites on
two inspected development sources. That observation prompted a general card/role
audit, not a task-ID exception: fixed-chunk-run's card explicitly describes
repeated-literal `.replace`, whereas vr11 required slicing; recursive-base-progress
had no operation implementation. These old sources/labels are development data.

Only these two operation-role implementations change behavior. Query strategy,
family diversity, corpus162cards, eight-record overlay,12candidate budget,
three-result cap, RRF/channels, binder precedence and fixed Jina encoder/model
remain as vr11. COPY_FROM_V11.json records the selective copy before edits;

source/outcomes are preserved. Engine/binder version labels identify vr13.

Fixed-chunk grounding requires an attribute `.replace` call with at least two
arguments and a repeated single-character string pattern of length>1. Accept
direct string literals or bounded literal-string × literal-integer multiplication
(maximum4096characters). No eval, dynamic constant execution or target execution.
A dynamic pattern remains unknown; a nonrepeated/single/empty pattern, bare
shadowed `replace` function or arbitrary slice is a mismatch. Attribute spelling
alone does not prove the receiver's runtime string type; the returned proposal
retains conditional status. A contract intentionally requesting fixed chunks is
not declared faulty merely because this operation is present.

Recursive grounding requires a call through a Name whose existing LibCST qualified
binding equals the enclosing lexical function's binding. A nested helper call,
parameter/local shadow and a nested body calling an outer function do not satisfy
this direct-self-recursion role. A recursive nested function can satisfy its own
role. Unknown resolution remains unknown. This does not prove progress failure,
missing base cases or supported depth. Existing recognized tier support retains
its conditional label; newly operation-grounded recursion is a test opportunity
whose contract requirements remain unknown. Mutual recursion and method dispatch
are outside this narrow role implementation.
