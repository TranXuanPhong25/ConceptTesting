# vr11: operation-grounded retrieval proposals

2026-10-29. Implementation and authored engineering checks are authorized. No new
development retrieval, dense inference, benchmark scoring or utility run before
independent read-only review and a source freeze. This is a separately versioned
development iteration; V7 and vr10 frozen implementations/outcomes remain intact.

## Motivation and exposure

Vr10's117source-review judgments exposed generic AST compatibility as a source
of unrelated proposals: regular calls nominated print redirection, reduction,
Unicode conversion, shared defaults or finally control flow. Those judgments and
their sources are now development evidence, not an independent holdout. V6/V7
operation recognition and vr8/vr9 gates are prior related attempts; this iteration
specifically screens source-level concept/site proposals before top3selection.
No hypothesis here is an implemented reproduction of a paper.

## Frozen ingredients

Corpus162cards, original eight-record overlay, V7A/B/C/D candidate channels,
RRF60,12unique-concept candidate budget,3maximum results, fixed Jina revision,
512token cap and CPU encoder are unchanged. Dense implementation and
MODEL_MANIFEST are byte-identical selective copies. No training/model swap.

Runtime receives public source and optional public query only. No task IDs,
reference/canonical bundle, gold, witness or reviewed judgment is available to
operation rules. Every added rule names a Python operation or a public-contract
clause rather than an individual benchmark program.

No replacement card, additional candidate count, retuned threshold or filling

Binder rules check the required operation at the exact proposed site. An absent
operation is unbound; an unimplemented role is unknown/unbound unless an existing
tier>=2local relation supports it. Operation presence creates a grounded test
opportunity, not a bug. Existing tier>=2relations retain the explicit
`source_supported_conditional_hypothesis` label. These two categories are reported
separately. Explicit distinct-count and case-insensitive public requirements can
exclude contradictory multiplicity/case-normalization hypotheses. These limited
text rules are incomplete and must be reviewed for negation/ambiguous contracts.

Coverage mode distributes64retained sites across the source, then uses up to four
interleaved mechanism slices, each1600characters with expressions shortened to88.
Fuse slices inside the mechanism view before fusing views/channel branches;
contract and trigger views are unchanged. Runtime encoder truncation counters
must still be reported: character limits do not guarantee a512token fit.
F deduplicates selected cards by the fixed overlay family, using concept ID for
unmapped families. F does not change channel rankings or candidate budget.

## Engineering checks before outcome computation

Authored fixtures distinguish distinct/occurrence requirements, min/max versus
empty-safe join, actual finally control versus an ordinary return, mutable
defaults versus None, case authorization versus preserved case, builtin
shadowing, unrelated calls and missing role implementations. A raising function
body remains unexecuted. Test that legacy A/C candidate lists and first sites
equal frozen V7 on a fixed authored fixture; no benchmark labels are involved.
Late-source encode operation must survive coverage slicing.

Engineering checks are not real-bug efficacy or semantic ground truth. Unknown
requirements can abstain; reduced return counts must be reported explicitly.

## Subsequent evaluation gate

Independent reviewer inspects implementation, API use, scope/alias handling,
controls and frozen thresholds before a new run. Required fixes become dated
append-only amendments. Root chooses a new fixed diagnostic manifest and records
its exposure before retrieval. Reusing vr10 is explicitly development regression
only. Never overwrite vr10 or treat its newly tuned outcomes as held-out gain.

Evaluate exact concept/site differences, returned/abstained counts, source-supported
versus opportunity mix, wrong-operation reductions, and losses of previously
supported bindings. Manual semantic review is required; generic old-label hits
do not establish applicability, and canonical proposals are not formal bug-report
false positives. No claim of better tests or more detected bugs without a later
matched downstream generation/oracle experiment in a new folder.

## Prospective independent-review amendment, 2026-10-29

Before new inference/outcome computation, reviewer identified an incorrect numeric
role and over-broad contract exclusions. `integer-division-precision` now requires
true division `/`, as its fixed card describes finite-precision float conversion;
floor division `//` alone does not ground that mechanism.

Distinct-cardinality exclusions now require a direct cardinality clause and no
occurrence/frequency/duplicate requirement. In particular, "number of occurrences
of each distinct value" remains unknown. Case exclusions require an explicit
non-negated authorization clause; never/not/retain/preserve or conflicting case
clauses prevent exclusion. Unresolved text stays unknown rather than inventing
scope. Expanded authored controls cover positive, negated, ambiguous and conflicting
requirements, as well as `/` versus `//`. Refresh implementation freeze after
these must-fixes, before any new development retrieval.

Further pre-inference review amendment,2026-10-29: builtin operation roles now
resolve qualified call targets through existing LibCST qualified-name metadata.
`builtins.min` and `from builtins import min as smallest` are grounded. Unresolved
callable aliases and shadowed builtin names remain unknown, not positive; an
unrelated known builtin remains an operation mismatch. Nested function/class/
lambda yields no longer make an outer function a generator. Rejected candidate
reason explicitly distinguishes failed operation grounding from AST-type absence.
Added engineering alias, shadowing and nested-yield controls before source refreeze.
